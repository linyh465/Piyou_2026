# 如何向 AI 提問 — Prompt 指南

> 針對 Piyou 專案的各種開發情境，提供結構化的提問模板，讓 AI 能更精準地幫助你。

---

## 通用提問原則

| 原則 | 說明 | ❌ 反例 | ✅ 正例 |
|------|------|---------|---------|
| **說清楚目標** | 你想達成什麼結果 | 「幫我改一下」 | 「讓成績頁面顯示班級排名」 |
| **給出上下文** | 涉及哪些檔案、函式 | 「頁面壞了」 | 「`Grades.jsx` 的排名欄位顯示 undefined」 |
| **描述現況** | 目前的行為是什麼 | 「它不對」 | 「點擊同步後 console 顯示 401 錯誤」 |
| **說明期望** | 正確的行為該是什麼 | 「幫我修好」 | 「應該顯示班排 5 / 系排 12 的格式」 |
| **提供限制** | 不能改的東西、必須遵守的規範 | （沒說） | 「不要改動 API 的回傳格式」 |

## 1. 🆕 新增功能

當你需要新增一個全新的功能時使用。

### 模板

```
請幫我新增「[功能名稱]」功能。

需求描述：
- [功能的具體行為 1]
- [功能的具體行為 2]

涉及範圍：
- 前端：[相關頁面/元件]
- 後端：[相關 API/路由]

參考：
- [可參考的現有功能或外部連結]

限制條件：
- [不能改動的部分]
- [需要相容的部分]
```

### 範例

```
請幫我新增「公車路線查詢」功能。

需求描述：
- 使用者可以在交通頁面選擇公車路線（例如 300 號）
- 顯示該路線的所有站點和預估到站時間
- 支援即時更新

涉及範圍：
- 前端：新增 Bus.jsx 頁面，修改 App.jsx 路由
- 後端：新增 /api/bus/routes endpoint

參考：
- 可參考現有的 transportData.js 的資料結構

限制條件：
- 不要改動現有的課表或成績功能
- 使用與現有頁面一致的 UI 風格
```

## 2. 🐛 修復 Bug

當功能出現異常行為時使用。

### 模板

```
請幫我修復以下 Bug：

問題描述：[簡短描述問題]

重現步驟：
1. [步驟 1]
2. [步驟 2]
3. [出現問題]

目前行為：[現在發生了什麼]
期望行為：[應該要怎樣]

錯誤訊息（如果有）：
[貼上 console 錯誤 / terminal 錯誤]

相關檔案：
- [可能出問題的檔案路徑]
```

### 範例

```
請幫我修復以下 Bug：

問題描述：課表頁面的上課時間顯示錯誤

重現步驟：
1. 登入後進入課表頁面
2. 查看第一節的上課時間

目前行為：顯示 08:00-08:50
期望行為：應該顯示 08:10-09:00（依照學校公告時間）

相關檔案：
- frontend/src/stores/timetableStore.js（時間計算邏輯）
- backend/app/services/transform.py（後端資料轉換）
```

## 3. 🔄 流程問題

當 Git 操作、CI/CD、開發流程出問題時使用。

### 模板

```
我在 [操作名稱] 時遇到問題：

目前情況：
- 當前分支：[分支名]
- 最近的操作：[做了什麼]

問題：[發生了什麼]
錯誤訊息：[如果有]

我希望達成：[最終目標]
```

### 範例

```
我在合併 dev 到 main 時遇到衝突：

目前情況：
- 當前分支：main
- 最近的操作：執行了 git merge dev

問題：frontend/src/App.jsx 出現合併衝突
錯誤訊息：CONFLICT (content): Merge conflict in frontend/src/App.jsx

我希望達成：保留 dev 分支的新路由設定，同時保留 main 上的 hotfix 修正
```

## 4. 🔒 資安問題

當涉及安全性的設計、漏洞修復、驗證邏輯時使用。

### 模板

```
請幫我檢查/修正以下資安問題：

問題類型：[認證/授權/資料驗證/注入攻擊/敏感資料洩漏]

目前情況：
- [現有的安全機制描述]
- [疑似有風險的程式碼位置]

風險描述：
- [可能被怎麼攻擊/利用]

期望：
- [需要達到的安全等級/標準]

相關檔案：
- [涉及的檔案路徑]
```

### 範例

```
請幫我檢查以下資安問題：

問題類型：認證與授權

目前情況：
- 登入使用學號密碼直接傳送
- backend/app/middleware/security.py 有做 CORS 設定

風險描述：
- API endpoint 沒有驗證 token，任何人都可以直接呼叫
- 密碼可能以明文存在 log 中

期望：
- 所有 API 需要驗證身份才能存取
- 敏感資料不得出現在 log 或錯誤訊息中

相關檔案：
- backend/app/middleware/security.py
- backend/app/routers/auth.py
```

## 5. ⚙️ 自動化問題

當需要設定 CI/CD、自動測試、自動部署等流程時使用。

### 模板

```
請幫我設定/修正以下自動化流程：

目標：[要自動化什麼]

目前狀態：
- [現有的自動化設定]
- [使用的工具：GitHub Actions / Docker / 其他]

預期行為：
- 觸發條件：[什麼時候觸發]
- 執行內容：[要自動做什麼]
- 成功條件：[怎樣算成功]

相關檔案：
- [CI/CD 設定檔路徑]
- [Dockerfile 路徑]
- [測試檔案路徑]
```

### 範例

```
請幫我設定 GitHub Actions 自動測試：

目標：每次 push 到 dev 時自動跑前後端測試

目前狀態：
- 有 .github/ 目錄但還沒設定 workflow
- 前端測試用 Vitest，後端測試用 pytest

預期行為：
- 觸發條件：push 到 dev 或 PR 到 main
- 執行內容：安裝依賴 → 跑 lint → 跑測試
- 成功條件：所有測試通過且無 lint 錯誤

相關檔案：
- frontend/src/test/*.test.jsx
- backend/tests/test_*.py
```

## 6. 🌐 全域修改

當需要大範圍修改（重構、統一風格、改共用元件）時使用。

### 模板

```
請幫我進行以下全域修改：

修改目標：[要改什麼]
影響範圍：[會影響哪些檔案/模組]

修改內容：
- [具體要改什麼 1]
- [具體要改什麼 2]

注意事項：
- [必須保持相容的部分]
- [不能影響的功能]

請先列出所有會受影響的檔案，讓我確認後再開始修改。
```

### 範例

```
請幫我統一所有頁面的深色模式支援：

修改目標：確保所有頁面都正確支援深色模式
影響範圍：frontend/src/pages/ 下的所有頁面元件

修改內容：
- 檢查所有頁面是否使用了 CSS 變數而非寫死顏色
- 統一 hover/active 狀態的顏色
- 確保圖表元件在深色模式下可讀

注意事項：
- 不要改動元件的功能邏輯
- 保持現有的 CSS 變數命名規則

請先列出所有會受影響的檔案，讓我確認後再開始修改。
```

## 7. 🔑 權限設定

當需要設定存取控制、角色權限、API 權限等時使用。

### 模板

```
請幫我設定/修改以下權限控制：

需求：[誰可以做什麼]

目前狀態：
- [現有的權限機制]
- [目前的問題或缺漏]

期望的權限規則：
- [角色 1] 可以 [操作 1]
- [角色 2] 不可以 [操作 2]

相關檔案：
- [權限相關的檔案路徑]
```

### 範例

```
請幫我設定 API 的存取權限：

需求：只有登入的學生可以存取個人資料 API

目前狀態：
- 登入後有取得 session token
- 但 API endpoint 沒有驗證 token

期望的權限規則：
- 已登入使用者：可以存取 /api/grades, /api/timetable, /api/tasks
- 未登入使用者：只能存取 /api/health 和 /api/bus（公開資料）
- 使用者只能存取自己的資料

相關檔案：
- backend/app/middleware/security.py
- backend/app/routers/auth.py
```

## 💡 進階提問技巧

### 1. 讓 AI 先分析再動手

```
請先分析 [檔案/功能] 的現有架構，列出你的修改計劃，
讓我確認後再開始實作。
```

### 2. 指定修改範圍

```
請只修改前端部分，後端 API 不要動。
```

### 3. 要求測試

```
修改完成後，請一併更新對應的測試檔案，並確認所有測試通過。
```

### 4. 要求解釋

```
請解釋你做了哪些修改、為什麼這樣改，
以及可能會影響到的其他部分。
```

### 5. 分階段進行

```
這個功能比較複雜，請分為以下階段進行：
1. 先完成後端 API
2. 再做前端頁面
3. 最後寫測試

每個階段完成後先讓我確認。
```
