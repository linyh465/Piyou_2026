高風險問題（需立即處理）
🚨
SQL Injection 完全未防護（12/12 未攔截）
OR 注入、Union、Time-based Blind、Error-based 等所有 Payload 均回傳 HTTP 200，WAF 未偵測到任何 SQL 注入特徵。
建議：啟用 WAF 的 SQL Injection 規則集（如 ModSecurity CRS）；後端使用 Prepared Statement；輸入端加強 allowlist 過濾。
🚨
速率限制未啟用（50 次並發請求全部通過）
50 個並發 GET 請求全部回傳 HTTP 200，無任何限速保護，暴力破解與 DDoS 風險高。
建議：在 Railway 或 Nginx/Caddy 設定速率限制（如每 IP 每分鐘最多 60 請求），並回傳 HTTP 429；考慮接入 Cloudflare。
🚨
敏感路徑回傳 HTTP 200（/.env、/.git/config、/admin/ 等）
共 9 個高危路徑（/.env、/.git/config、/wp-config.php、/admin/、/backup.zip 等）均回傳 HTTP 200 + 1794 bytes。推測為 SPA fallback 回傳 index.html，但需確認內容不含機敏資訊。
建議：確認這些路徑的實際回應內容；對敏感路徑明確設定 HTTP 404 或 403 規則，而非依賴 SPA fallback。
🚨
惡意掃描器 User-Agent 未被封鎖（sqlmap、Nikto、Nmap）
sqlmap、Nikto、Nmap 等知名攻擊工具的 UA 字串均可正常存取，代表 WAF 未設定 Bot 特徵過濾。
建議：在 WAF 或反向代理設定已知惡意 UA 的封鎖規則；使用 Cloudflare Bot Management 或 fail2ban。
中風險問題（建議改善）
⚠️
缺少 HSTS Header（Strict-Transport-Security）
未設定 HSTS，瀏覽器不會強制使用 HTTPS，存在 SSL Stripping 降級攻擊風險。
建議：加入 Strict-Transport-Security: max-age=31536000; includeSubDomains
⚠️
缺少 Permissions-Policy Header
未限制瀏覽器功能（camera、microphone、geolocation 等），可能遭濫用。
建議：加入 Permissions-Policy: camera=(), microphone=(), geolocation=()
⚠️
Server Header 洩漏平台資訊（railway-edge）
攻擊者可得知您使用 Railway 部署，可針對性尋找 Railway 平台已知漏洞。
建議：在反向代理層隱藏或覆蓋 Server Header，回傳空值或偽裝值。
⚠️
CONNECT 方法未明確封鎖（回傳 HTTP 400）
CONNECT 方法回傳 400 而非 405，代表方法本身有被處理，可能被用於代理穿透攻擊。
建議：在 WAF 規則明確回傳 HTTP 405 並封鎖 CONNECT 方法。
